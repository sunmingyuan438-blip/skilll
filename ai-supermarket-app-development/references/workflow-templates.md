## 开发交接提示词

```text
你接手的是一个已经完成产品发现、外部研究和方案确认的 AI 超市应用。

先阅读仓库和以下资料，先给实施计划，不要直接大范围修改代码。

【产品简报】
【外部研究快照】
【MVP MUST】
【明确 OUT】
【核心用户流程】
【AI 与确定性逻辑边界】
【AIGZM 接入决策】
【已读取的官方文档和日期】
【模型/数据 API 的实时 key】
【OAuth / Billing / Webhook 需求】
【会员、钱包和应用购买权益】
【托管模板、部署包和环境变量】
【数据库连接、迁移、seed 和 SQL 管理】
【待验证假设】

硬性要求：
1. AIGZM 字段和路径以 OpenAPI 为准，模型和数据接口以实时官方索引为准，不能猜测或保存静态白名单。
2. 先选择唯一身份模式，不混用 API Key、Cookie、Client Secret 和 OAuth Token。
3. 所有凭据只放服务端；请求、日志和错误上报不得泄露敏感信息。
4. 为调用设置合适超时、幂等键、错误映射和不重复扣费保护。
5. Sandbox、生产、用户数据、Webhook、日志和凭据保持隔离。
6. 如果采用开源项目，记录仓库、版本、许可证、修改范围和履行义务。
7. 用测试或手工验收证明核心价值闭环、AIGZM 接入和失败兜底。
8. 如果产品进入 AI 超市发布流程，核对 homepage_url、OAuth 回调、支付回跳、Scope、Webhook 和审核状态。
9. 会员、钱包、应用购买权益、支付状态和 Webhook 必须按官方接口查询与验签，不能只相信前端回跳。
10. 托管部署遵循 zip 根目录、模板构建、`PORT`、健康检查、只读文件系统和 `DATABASE_URL` 约束；环境变量修改后重新部署。

如果以上资料存在冲突或关键字段为空，只提出一个最关键的问题，不要自行猜测后开始编码。
```
